# Urban Climate Resilience (UCR): แปลงข้อมูลภาคสนามเป็นข้อมูลออกแบบ
**จัดทำโดย:** TONKIT Laboratory (21 May 2026)

เอกสารฉบับนี้สรุปแผนการดำเนินงานของทีมที่รับผิดชอบในการเก็บและจัดการข้อมูลภาคสนาม เพื่อสนับสนุนทีมออกแบบในการแก้ไขปัญหาการเปลี่ยนแปลงสภาพภูมิอากาศในระดับชุมชนเมือง (ความร้อน, น้ำท่วม, การเข้าถึง)

---

## 1. โจทย์และเป้าหมายของทีมออกแบบ
ทีมออกแบบต้องการทำความเข้าใจผลกระทบจาก **ความร้อน น้ำท่วม และข้อจำกัดของพื้นที่อยู่อาศัย** เพื่อนำไปสู่แนวทางออกแบบใน 4 มิติ:
1. **บ้าน / ที่อยู่อาศัย:** ความร้อน น้ำท่วม การระบายอากาศ และความปลอดภัย
2. **พื้นที่ระหว่างบ้าน / ทางเดิน:** ทางเดิน จุดแคบ สิ่งกีดขวาง การเข้าออก และการใช้งานจริง
3. **โครงสร้างพื้นฐานร่วม:** ทางเข้าออก ทางระบายน้ำ แสงสว่าง และพลังงานพื้นฐาน
4. **ศูนย์ชุมชน / พื้นที่ส่วนกลาง:** บทบาทของพื้นที่ในวันปกติและวันเกิดภัย

### สิ่งที่ทีมออกแบบต้องการจากข้อมูล (ผ่าน Focus Group)
เป้าหมายคือการเก็บข้อมูลเพื่อทำความเข้าใจจุดเสี่ยง จุดร้อน จุดน้ำท่วม จุดเข้าออกยาก การใช้พื้นที่ กลุ่มเปราะบาง และความต้องการเชิงออกแบบ
* จุดไหนร้อน ท่วม หรือเดินลำบาก?
* ใครใช้พื้นที่นั้น และใช้ช่วงเวลาไหน? (กลุ่มไหนได้รับผลกระทบมากที่สุด)
* พื้นที่ไหนควรปรับปรุงก่อน?
* พื้นที่ส่วนกลางควรทำหน้าที่อะไรในสถานการณ์ปกติและช่วงเกิดภัย?
* **กำหนดการ Focus Group:** วันที่ 7 มิ.ย., 14 มิ.ย., และ 21 มิ.ย.

## 2. เป้าหมายของทีมเก็บข้อมูล (Data Team)
เก็บและจัดระเบียบข้อมูลจากภาคสนามและชุมชน เพื่อสร้างหลักฐานประกอบการออกแบบ (Evidence-based design) ตอบคำถามว่า “ปัญหาเกิดที่ไหน เกิดกับใคร และควรพิจารณาอะไรต่อ” โดยเน้นที่:
* **จุดใช้งานสำคัญ:** พื้นที่ที่คนใช้จริง เวลาที่ใช้ และกลุ่มผู้ใช้
* **ปัญหาเชิงกายภาพ:** ร่มเงา ทางเดิน สิ่งกีดขวาง วัสดุพื้น อาคาร
* **จุดเสี่ยง / จุดเปราะบาง:** จุดร้อน จุดน้ำท่วม จุดที่เดินลำบาก
* **ข้อสังเกตเพื่อการออกแบบ:** สรุปประเด็นไปหารือกับทีมออกแบบ เช่น การเพิ่มร่มเงา ปรับทางเดิน

### แหล่งข้อมูล 3 ส่วน (Data Sources)
1. **Sensor (ตัวเลข):** อุณหภูมิ ความชื้น แสง/UV ระดับเสียง เวลา ตำแหน่ง -> *ตอบโจทย์: จุดไหนร้อนจริง ร้อนช่วงไหน ควรพักคลายร้อนตอนไหน*
2. **Street Images (หลักฐานเชิงกายภาพ):** ร่มเงา หลังคา ทางเดิน สิ่งกีดขวาง วัสดุพื้น ถังขยะ ไฟ -> *ตอบโจทย์: พื้นที่นี้มีปัญหาเชิงกายภาพอะไร ควรตรวจจุดไหนต่อ*
3. **ChatBot (ประสบการณ์จริงจากชุมชน):** จุดที่ชุมชนแจ้ง ปัญหาที่เจอ ผู้ได้รับผลกระทบ -> *ตอบโจทย์: คนในพื้นที่เจออะไร กระทบใคร เรื่องไหนสำคัญสุด*

## 3. Data Schema (โครงสร้างข้อมูลมาตรฐาน)
เพื่อให้ทุกทีมย่อยทำงานร่วมกันได้ ข้อมูลทั้งหมดจะต้องถูกบันทึกตาม Schema เดียวกัน:
* **ตำแหน่งและเวลา:** `community/zone`, `point_id`, `date_time`, `gps / landmark`
* **ข้อมูลกายภาพ:** `temperature / humidity / UV`, `shade condition`, `roof cover`, `usable width`, `obstruction`
* **ประเภทปัญหา:** `issue_type` (heat, flood, access, housing, community_space, outage)
* **บริบทและหลักฐาน:** `affected_group`, `time_pattern`, `severity`, `evidence note`, `design_note`, `photo_id`

---

## 4. โครงสร้างทีมและการแบ่งงาน (4 ทีมย่อย)
**1. ทีม Field Data / Sensor:**
* **หน้าที่:** วางแผนเส้นทาง เก็บค่าอุณหภูมิ ความชื้น UV ถ่ายภาพ Street image พร้อมเวลาและตำแหน่ง
* **Output:** ตาราง sensor readings + location และ ภาพ street image ที่ครอบคลุมหลายช่วงเวลา

**2. ทีม Street Image Indicator:**
* **หน้าที่:** จัดรูปตามเส้นทาง วิเคราะห์ภาพด้วย AI เพื่อดึง indicator (ร่มเงา, สิ่งกีดขวาง, ความกว้างทางเดิน)
* **Output:** ตาราง street image indicators และ Map จุดที่แคบ/ร้อน/ไม่มีร่ม

**3. ทีม ChatBot / Community Report:**
* **หน้าที่:** เตรียมคำถาม Chatbot รับข้อมูลตรงจากชุมชน แปลงคำตอบเป็น Tag (heat, flood, access, urgent, elderly)
* **Output:** ChatBot question flow และ Issue/Priority list + Summary

**4. ทีม Visualization & Simulation:**
* **หน้าที่:** นำข้อมูลมาแสดงผลเพื่อให้ทีมออกแบบเข้าใจง่าย เริ่มจาก Visualization ก่อน แล้วค่อยทำ Simulation
* **Phase 1 (Visualization):** Map จุดสำรวจสีตาม Heat index/Shade, แยก Layer ของข้อมูล, ปัก Icon จุดน้ำท่วม/สิ่งกีดขวาง
* **Phase 2 (Sun/Shade Study):** วิเคราะห์ทิศทางแดด เงาอาคาร เปรียบเทียบช่วงเวลา (10:00, 13:00, 16:00) เพื่อหาจุดที่ควรเพิ่มร่มเงา
* **ข้อมูลที่ต้องการจากทีมอื่น:** แผนที่/Footprint อาคาร, ความสูง, ทิศเหนือ (Bearing), พิกัด GPS จุดสำรวจ, ภาพ Street View

## 5. บทบาทพิเศษและการบริหารจัดการ (Project Management)
* **Technical & Integration Lead (พี่โชกี้):** ดูแลทิศทางเทคนิค Data schema, Repo structure, จ่ายงาน และรวมข้อมูลจากทุกทีมให้เชื่อมกันได้
* **Project Coordinator:** ประสานงาน นัดหมาย จดสรุป Action items ติดตามความคืบหน้าไม่ให้หลุด Deadline
* **รูปแบบการทำงาน:** แนะนำให้มี Short sync 15 นาที/สัปดาห์ ระหว่างอาจารย์ (PIs), พี่โชกี้ และ Coordinator ก่อนประชุมทีมใหญ่ เพื่อเคลียร์ Blocker และตัดสินใจเรื่องเทคนิค

## 6. เป้าหมายการวิจัยและโอกาสต่อยอด (Research & Opportunities)
โปรเจกต์นี้สามารถต่อยอดเป็นงานวิจัยและสร้าง Impact ได้ในหลายด้าน:
1. **Bangkok Alley Morphology Dataset:** ชุดข้อมูลซอยในกรุงเทพฯ
2. **Urban Issue Mapping:** แผนที่จุดร้อน/น้ำท่วม จากการรวมข้อมูลหลากหลายแหล่ง
3. **LLM Consistency for Street Image Indicator Extraction:** ใช้ AI วิเคราะห์ภาพ
4. **Community Resilience Data Platform & Digital Twins:** แพลตฟอร์มรวมข้อมูลสนับสนุนการออกแบบ
5. **Resource-Aware Edge-Cloud-Serverless Workflow:** การประมวลผลข้อมูลที่มีประสิทธิภาพ (เช่น เบลอภาพส่วนตัวที่ Edge ก่อนขึ้น Cloud)
