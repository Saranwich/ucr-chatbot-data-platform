# แบบร่างคำถามเพื่อสรุปความต้องการ (Advisor Interview Guide) - REFINED
**วันที่ (Date):** 2026-05-12
**โครงการ (Project):** UCR Smart City Chatbot (Architecture Team Support)
**กลุ่มเป้าหมาย (Target Group):** ชาวบ้านในพื้นที่ (เน้นกลุ่มอายุ 40-60+ ปี)

---

## 🛠️ ส่วนที่ 1: ขั้นตอนการใช้งาน (User Journey)

1. **การลงทะเบียนเริ่มต้น (Initial Onboarding)**
   - คำถาม: เมื่อผู้ใช้งานกดเพิ่มเพื่อน (Add Friend) ควรให้เขาลงทะเบียนข้อมูลส่วนตัวก่อน (เช่น อายุ/โซนที่พัก) หรือควรปล่อยให้เริ่มรายงานปัญหาได้ทันทีเพื่อความรวดเร็ว? (When they add the bot, should they register their profile first, or let them report a problem immediately to reduce friction?)
   - [คำตอบ]: **Optional (ไม่บังคับ)** - ให้เริ่มใช้งานได้ทันทีเพื่อลดความยุ่งยาก จะเก็บข้อมูลโปรไฟล์เฉพาะเมื่อผู้ใช้สมัครใจเท่านั้น (Prioritize low friction; allow reporting without mandatory registration).

2. **รูปแบบการกระตุ้นให้ส่งข้อมูล (Survey Trigger)**
   - คำถาม: ควรเป็นแบบ "รายงานเมื่อเจอ" (กดปุ่มรายงานเอง) หรือ "ส่งข้อความถามรายสัปดาห์" (บอททักไปถามตามเวลาที่กำหนด)? (Should the survey be 'On-Demand' via button click, or 'Scheduled' where the bot sends a weekly prompt?)
   - [คำตอบ]: **Hybrid / Weather-Based** - เน้นให้กดรายงานเอง แต่เพิ่มระบบตรวจสอบสภาพอากาศ (Weather API) เพื่อส่งคำถามที่สอดคล้องกับสถานการณ์ เช่น "วันนี้ฝนตก มีน้ำขังไหม?" (Mainly on-demand, with weather-driven push notifications as a secondary trigger).

3. **ความละเอียดของขั้นตอน (Reporting Flow)**
   - คำถาม: อยากให้การรายงานจบในคลิกเดียว (เช่น กดปุ่มขยะ -> ส่งพิกัด -> จบ) หรือต้องการรายละเอียดเพิ่ม (เช่น เลือกประเภท -> ระบุความรุนแรง 1-5 -> ถ่ายรูป -> ส่งพิกัด)? (Do you want a 'One-Click Report' or a 'Detailed Survey' with multiple steps like severity levels and photos?)
   - [คำตอบ]: **LIFF Redirect** - สำหรับการรายงานปัญหา (Report) ให้เปิดเป็นหน้า Website (LIFF) ที่ดึง URL จากไฟล์ Config โดยตรง เพื่อให้ใช้งานง่ายและกรอกข้อมูลได้ละเอียดกว่าในแชท (Use a LIFF web-view for the main reporting flow to improve UI/UX).

---

## 🎨 ส่วนที่ 2: หน้าตาและการโต้ตอบ (UI/UX)

4. **รูปแบบการกรอกข้อมูล (Input Style)**
   - คำถาม: สำหรับกลุ่มอายุ 40-50+ ควรปิดช่องพิมพ์ข้อความแล้วให้กดแค่ปุ่ม (Quick Reply) อย่างเดียวเพื่อป้องกันการพิมพ์ผิดหรือไม่? (For the 40-50+ group, should we disable text input and only use 'Quick Reply' buttons to prevent errors?)
   - [คำตอบ]: **Hybrid Input** - เน้นการใช้ปุ่ม Quick Reply เป็นหลักเพื่อความง่าย แต่ยังเปิดให้ใช้งานคีย์บอร์ด (Keyboard Enabled) สำหรับผู้ที่ต้องการพิมพ์รายละเอียดเพิ่มเติม (Primary focus on buttons, but keep keyboard open for detailed comments).

5. **เมนูหลักด้านล่าง (Rich Menu Design)**
   - คำถาม: ปุ่ม 3-4 ปุ่มที่ควรค้างไว้ที่หน้าจอแชทตลอดเวลาควรมีอะไรบ้าง? (e.g. รายงานปัญหา, ดูแผนที่ชุมชน, ติดต่อเจ้าหน้าที่) (What are the 3-4 most important buttons that should always be on the Rich Menu?)
   - [คำตอบ]: **4 ปุ่มหลัก (4-Button Layout):**
     1. [เริ่มแชท/แบบสำรวจ] - Chat with Quick Replies
     2. [รายงานปัญหา] - Opens LIFF Website
     3. [ข้อมูลโครงการ] - Static Project Details
     4. [สรุปผล] - Placeholder (Coming Soon)

6. **ความแม่นยำของแผนที่ (Map Precision)**
   - คำถาม: การส่งพิกัดแบบปกติของ LINE เพียงพอไหม หรือต้องมีหน้าแผนที่พิเศษ (LIFF) เพื่อให้เขาเลือกจุดที่ต้องการได้แม่นยำขึ้น? (Is the standard LINE location picker enough, or do we need a custom Map (LIFF) for better precision?)
   - [คำตอบ]: **Hybrid Approach (ใช้ทั้งสองแบบ)** - ใช้การส่งพิกัดแบบปกติของ LINE ในชุดคำถามทั่วไปเพื่อความรวดเร็ว แต่ใช้หน้าแผนที่พิเศษ (LIFF) เมื่อผู้ใช้กดรายงานปัญหาผ่าน Rich Menu เพื่อความแม่นยำและแสดงจุดรายงานอื่นในพื้นที่ (Use Native LINE picker for quick chat surveys; use custom LIFF Map for detailed reporting via Rich Menu).

---

## 📊 ส่วนที่ 3: การสรุปผลและข้อมูล (Result & Data)

7. **การตอบกลับเมื่อเสร็จสิ้น (Confirmation)**
   - คำถาม: หลังจากเขาส่งข้อมูลเสร็จ ควรตอบกลับเป็นข้อความขอบคุณธรรมดา หรือเป็น "การ์ดสรุปรายการ" (Flex Message) ที่สวยงามเพื่อให้เขาภูมิใจ? (Should the user get a simple 'Thank you' text, or a beautiful 'Summary Card' (Flex Message) to show their contribution?)
   - [คำตอบ]: **Standard Text** - ในเฟสแรกใช้ข้อความขอบคุณแบบปกติไปก่อนเพื่อความรวดเร็วในการพัฒนา (Simple text thank-you for the initial phase).

8. **การแสดงผลลัพธ์กลับไปยังชุมชน (Visual Feedback)**
   - คำถาม: ชาวบ้านควรจะสามารถกดดู "แผนที่รวมปัญหา" ทั้งหมดใน LINE ได้เองเลยไหม หรือข้อมูลนี้ควรให้ทีมสถาปนิกดูผ่าน Dashboard หลังบ้านอย่างเดียว? (Should residents be able to see a 'Live Map' of all reports inside LINE, or is it only for the Architecture Team's dashboard?)
   - [คำตอบ]: **Public Access** - ทุกคนสามารถกดดูผลลัพธ์หรือ Dashboard เบื้องต้นได้ เพื่อสร้างการมีส่วนร่วมและความโปร่งใส (Transparency; allow residents to view a simplified version of the results map).

## 📝 บันทึกเพิ่มเติมสำหรับนักพัฒนา (Developer Notes)
*   **Location Strategy:** รองรับ Hybrid model (Chat = Native, Menu/Report = LIFF) เพื่อความยืดหยุ่นสูงสุดสำหรับกลุ่มเป้าหมาย
*   **Branching Logic:** เตรียมระบบแชทให้รองรับการเลือกชุดคำถามตามคำตอบ (เช่น ตอบ A ไปถามชุด X) โดยจะเริ่มทำหลังจากจบเฟส 1
*   **Weather API:** ออกแบบระบบให้รองรับการดึงข้อมูลอากาศเพื่อ Trigger คำถามอัตโนมัติ (เป็นเป้าหมายรอง)
*   **No Legal/PDPA:** ส่วนของกฎหมายและ PDPA ไม่อยู่ในขอบเขตงานของทีมนักพัฒนาในตอนนี้
